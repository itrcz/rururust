# Аудит фундамента ruru: находки и план доводки

Главное: «странные рамки на углах» — это расхождение формы клипа и формы фона, плюс скругление у нас не такое, как в референсе. Производительность ленты на ленивом `list` уже хорошая; узкие места — стриминг длинного абзаца, вытеснение кэша текста и стекло.

Мерил на снимке HEAD `6fc736e`: рабочее дерево в момент аудита не собиралось (`view.rs` в правке, нет `ui::popup`). Строки `ui.rs`/`view.rs` ниже — по этому снимку. Исходники не трогал.

## Производительность

Замеры: release, M-серия, окно 1082×680 pt, 2x; бенч в `audit/bench`.

| № | Узкое место | Цифры | Устранение | Выигрыш |
| --- | --- | --- | --- | --- |
| 1 | Стриминг перешейпливает весь абзац каждый кадр, причём дважды: `measure` сначала шейпит без переноса, потом с переносом (`text.rs:231-233`). | 0.59 мс при 500 знаках, 2.1 мс при 2000, 5.3 мс при 8000; аллокаций 591 → 6110 на кадр. ## Пакеты работ (по убыванию заметности)

1. **Углы** (engineer; `quad.wgsl`, `ui.rs`). Клип той же формой; окружность по умолчанию и `.smooth()`; обводка контейнера поверх детей и hover. Приёмка: в `audit/shots/c_ref_vs_grom_corners.png` рамка панели непрерывна по дуге, контур совпадает с референсом до 0.5 px (скрипт `audit/edge.py`); тест на попадание клика в скруглённый угол; web пересобрать.
2. **Пиксельная сетка** (engineer; `ui.rs`, `headless.rs`, `app.rs`). `Ui.scale`, привязка квадов, текста и скролла, минимум 1 px. Приёмка: в `probe` линия 0.5 pt на 2x — одна строка 255 при любом смещении; края фона без полутона в покое; тест — скролл на дробное смещение не меняет профиль линии.
3. **Тема и токены** (architect → coder). Эскиз ниже. Приёмка: в `ui.rs`/`view.rs` не осталось литералов цветов; showcase в светлой и тёмной теме кадром; тест — переопределённый акцент доходит до button/toggle/slider.
4. **Тени** (engineer; `view.rs`, `ui.rs`, шейдер). `x`, `spread`, два слоя, inset-кромка; пресеты в теме. Приёмка: кадр меню/поповера рядом с системным.
5. **Текст: один буфер и LRU** (engineer; `text.rs`). №1 и №2 из таблицы. Приёмка по `audit-bench extra`: стриминг 2000 знаков ≤ 1 мс, скролл назад ≤ 0.1 мс медиана; существующие тесты `text.rs` зелёные.
6. **Типографика** (coder). `.tabular()`, разрядка заголовков в теме, опция системного шрифта, хинтинг выключен на 2x. Приёмка: кроп строки ленты рядом с референсом, плотность краски в пределах 2 %.
7. **Стекло и пропуск кадра** (engineer; `render.rs`). №3 и №5. Приёмка: GPU-кадр со стеклом ≤ 1.2 мс в том же бенче, кадр стекла не изменился попиксельно.

Пакеты 1 и 2 трогают `ui.rs` и шейдер — последовательно. 5 и 6 оба правят `text.rs` — тоже последовательно; параллельно с 1–2 можно пускать только один из них.

## Тема: эскиз

```rust
#[derive(Clone)]
pub struct Theme {
    pub dark: bool,
    pub color: Palette,       // bg, surface, raised, text, text_muted, border, divider, accent, on_accent, hover, pressed, selection, danger
    pub space: [f32; 7],      // 2 4 8 12 16 24 32
    pub radius: Radii,        // xs 4, s 6, m 8, l 12, xl 22
    pub text: TypeScale,      // caption/body/title/heading: TextStyle { size, line_height, weight, tracking }
    pub control: Controls,    // height s/m/l = 22/28/36, pad_x, border = 0.5, focus_ring = 3
    pub shadow: Shadows,      // control, popover, window: [Shadow; 2]
    pub motion: Motion,       // fast 0.12, base 0.2, slow 0.35; spring crisp / smooth / bouncy
}
impl Theme { pub fn light() -> Self; pub fn dark() -> Self; pub fn accent(self, c: Color) -> Self; }

App::new(state, view).theme(Theme::dark().accent(Color::hex(0x4D81EF)));   // либо ui.theme = …
fn view(s: &State, env: &Env) -> View<State> { let t = &env.theme; … }      // Env получает Rc<Theme>
text("…").style(t.text.body);                                               // один модификатор вместо четырёх
```

Встроенные виджеты читают тему в `layout`/`Painter` (в `Lx` и `Painter` кладётся `&Theme`), конструкторы перестают зашивать цвета. `Theme` — обычная структура с публичными полями: приложение правит поля, макросов и строковых ключей нет. Запись в `docs/decisions/003-theme.md` — до кода.

## Сознательно не делать сейчас

- Свой рендер текста, LCD-субпиксели, смешивание в линейном пространстве — выигрыш мал, риск большой.
- Offscreen-слои для групповой прозрачности и вложенных клипов.
- Dirty-rect и частичная перерисовка; мемоизация всего дерева: при ленивой ленте кадр уже 0.05 мс.
- Обводка center/outside, сквиркл «как в iOS» с точной кривой, ось `opsz` (не даёт cosmic-text 0.19).
- Каскадные темы на поддерево — пока хватает одной темы на окно.

## Что проверено чем

- **Кадром и числом:** клип и обводка, форма скругления, hairline, толщина обводки, центровка текста, плотность шрифта, тени.
- **Замером:** всё в таблице производительности.
- **Только чтением кода:** групповая прозрачность, hover поверх обводки, обводка стекла под фоном, хинтинг.
- **Не проверено:** живое окно и настоящий Safari (это за человеком), текст на 1x рядом с CoreText, web-сборка, кадр GromAgent целиком.
