# Оконные кнопки в содержимом

`View::window_action(WindowRequest)` использует обычный tap: disabled, модальные слои,
отмена клика и приоритет над перетаскиваемой шапкой остаются общими для всех кнопок.
Запрос передаётся раннеру после обработчика, как запрос копирования. Ядро не зависит от winit.
`Env::window_maximized` отражает состояние окна, а не предполагаемый результат нажатия.

На Windows `Titlebar::Overlay` убирает системную шапку. Приложение рисует кнопки,
а раннер передаёт перетаскивание краёв в `Window::drag_resize_window`; новая платформенная
зависимость и unsafe не нужны. В модальном интерфейсе приложение располагает оконные
кнопки в верхнем слое: оконные действия не обходят изоляцию модалки.

Закрытие превращается в тот же запрос, что системное CloseRequested: главное окно
завершает event loop, companion вызывает свой обработчик закрытия. Web игнорирует
оконные действия; macOS сохраняет нативный светофор.

## Ограничение Wine 11.0 на macOS

В проверке Grom через Wine 11.0 (пакет Gcenx 11.0_1) minimize, maximize/restore
и close выполняются. Однако при maximize Wine добавляет заголовок хостового Cocoa-окна
и перекрывает верхнюю часть содержимого. Обычное непрозрачное окно отображается правильно.
Настоящая Windows в этой проверке недоступна: Wine не заменяет визуальную проверку на ней.

Это не включение декораций из ruru. В локальном winit 0.30.13 `set_maximized`
меняет только флаг `MAXIMIZED` и вызывает `ShowWindow(SW_MAXIMIZE/SW_RESTORE)`.
Для top-level окон winit специально сохраняет `WS_CAPTION` ради системных жестов
и Aero Snap, а borderless реализует через `WM_NCCALCSIZE`; при maximize клиентская
область ограничивается рабочей областью монитора. Измеренные `GWL_STYLE`:
`0x16cf0000` до maximize и `0x17cf0000` после — добавляется только
`WS_MAXIMIZE = 0x01000000`, флаг caption не меняется.

[Mac-драйвер Wine 11.0](https://github.com/wine-mirror/wine/blob/wine-11.0/dlls/winemac.drv/window.c#L54-L90)
сам определяет наличие Cocoa title bar по `WS_CAPTION` и соотношению оконных прямоугольников.
В сочетании с наблюдаемым поведением это указывает на ограничение совместимости Wine
с borderless maximize winit. Попытка `Mac Driver/Decorated=N` с перезапуском
изолированного Wine prefix не помогла; специальный обход Wine в продукт не добавляем.
При изменении winit или Wine повторяем проверку и сравниваем client/window rects.
