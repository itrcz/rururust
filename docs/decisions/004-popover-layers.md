# 004. Поповеры, меню и тултипы — слои над деревом

**Решение.** Плавающее содержимое (поповер, меню, контекстное меню, тултип, подменю) крепится к
узлу-якорю (`View::extra`, в коробке, чтобы обычный узел не рос). Layout раскладывает его сразу
после якоря в `LNode::pop` / `LNode::tip` по естественному размеру и только пока оно открыто или
гаснет — один проход сохраняется. Paint кладёт его в очередь `Layer` и красит все слои после
дерева (вложенные — следом, тултипы — последними), поэтому и пиксели, и `Hit` сверху.

- Позиция: сторона + выравнивание + зазор, переворот на другую сторону, если не помещается, и
  сдвиг внутрь окна (`popup::place`).
- Закрытие: открытый слой кладёт под собой `Action::Outside` на всё окно; нажатие по нему только
  закрывает (как в macOS), колесо не проходит, Escape закрывает верхний.
- Кто держит флаг: `.popover(open, ..)` — приложение (`on_dismiss`); `.menu()` /
  `.context_menu()` — ядро (`Ui::open_menu`, как у `picker`).
- Меню — отдельный `Kind::Menu`, а не дерево из stack-ов: подсветка, подменю и клавиатура живут в
  `Ui::menu_state` по id меню; подменю раскладываются вместе с меню (они маленькие), открываются
  без повторного layout.
- Тултип ждёт через `wake_in`, а не кадрами; он слой без ввода (его `Hit`/`Zone` отбрасываются).
- Шорткаты собираются из нарисованного дерева в каждом кадре; раннер спрашивает
  `Ui::key_shortcut` до обычной обработки клавиши.

**Почему.** Якорь знает своё место только после layout, а слой должен быть выше всего по Z — так
это ложится на существующие `Hit`/`Action` и `child_id` без второго прохода и без отдельного
«корневого» API, где пользователь сам сводил бы ключи якорей.
