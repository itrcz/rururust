# 008. Живая перерисовка во время macOS zoom

Двойной клик вызывает `WindowRequest::Zoom` из обработчика ввода winit. Синхронный
`NSWindow::zoom` внутри этого обработчика удерживает его до конца системной анимации;
winit откладывает вложенные `Resized`, потому что `event_handler.in_use()` остаётся true.

На macOS планируем `zoom:` через main run loop с нулевой задержкой. Обработчик ввода
успевает вернуться, поэтому события каждого изменения размера доставляются сразу.
В каждом `Resized` уже выполняется layout и Metal present в транзакции AppKit.
Остальные платформы сохраняют `set_maximized`.

Для кастомного заголовка `NSWindow.movable` выключен между событиями: наведение на
`.window_drag()` не включает нативные жесты заголовка. Иначе AppKit и ruru могут обработать
один двойной клик и дважды переключить zoom. Нативное перемещение включается только на
время явного вызова `drag_window` после hit-test, затем снова выключается. Окна с системным
заголовком сохраняют обычное поведение.

Размещение traffic lights защищено от повторного входа уведомлений. Шаг между кнопками
запоминается до первой правки; контейнер привязан к текущему верху родительского view,
наблюдаются также titlebar view и все три кнопки. Собственные изменения фреймов выполняются
без неявных Core Animation actions. В fullscreen геометрией по-прежнему управляет AppKit.
