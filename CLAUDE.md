# ruru

Цель: **лёгкий, быстрый, удобный и гибкий** фреймворк для кроссплатформенных приложений
(macOS / Windows / Linux / iOS / Android / web-canvas) на Rust. Каждое решение проверяй этими
четырьмя словами; если фича делает ядро тяжелее — она идёт под cargo-фичу.

Первый продукт на фреймворке — чат с LLM-агентом (markdown, код, картинки, системные блоки в ленте).
Что делать дальше и в каком порядке — `docs/ROADMAP.md`. Обзор API для людей — `README.md`.

## Команды

```sh
cargo test                                                    # ядро без GPU, ~2 c
cargo run --release --example showcase                        # окно
cargo run --release --example showcase -- --screenshot out.png [tab] [frames] [width]   # кадр без окна
cargo run --release --example stress -- out.png               # текст под нагрузкой
./web/build.sh && python3 -m http.server -d web 8080          # web
cargo check --no-default-features --features "<набор>" --lib  # проверить, что фичи не сломаны
```

## Карта кода

| Файл | Ответственность |
| --- | --- |
| `src/view.rs` | `View<S>`, `Kind`, `Style`, конструкторы и модификаторы — весь публичный API виджетов |
| `src/layout.rs` | `layout()` — один проход, родитель предлагает размер; `child_id()` |
| `src/ui.rs` | `Ui<S>`: кадр, `Painter` (дерево → `DrawList`), пружины, физика скролла, ввод, таймеры |
| `src/render.rs` | wgpu: батчи, снимок сцены и пирамида размытия для стекла, текстуры картинок, текст через glyphon |
| `src/shaders/quad.wgsl` | все фигуры одним инстансным шейдером; `blur.wgsl` — пирамида |
| `src/theme.rs` | `Theme`: палитра, шкала текста, метрики контролов, тени, пружины; `theme::apply` дописывает их в дерево после `view()` |
| `src/text.rs` | шейпинг и кэш (cosmic-text); кэш высот строк `list`; выбор шрифта (`Font`: системный, фолбэк на Inter), OpenType-фичи; геометрия текста: `hit`, `caret`, `range_rects`, `word_at`, `para_at` |
| `src/edit.rs` | редактор `text_field` (подмодуль `ui`: видит его поля): каретка, выделение, undo, буфер, IME, multiline |
| `src/popup.rs` | слои поверх дерева (подмодуль `ui`): поповеры, меню с подменю и клавиатурой, контекстное меню, тултипы; `Placement`, `MenuStyle`, шорткаты |
| `src/task.rs` | канал «фон → состояние»: `Link`, `Task`, `spawn`, `sleep`, `Ui::pump` |
| `src/app.rs` | winit: окно, события, пробуждения; единственное место, знающее про платформу |
| `src/macos.rs` | AppKit, чего нет в winit: подложка `NSVisualEffectView`, место светофора; вызывается только из `app.rs` |
| `src/markdown.rs`, `src/headless.rs` | под фичами `markdown`, `headless` |

Поток кадра: `state → view(&S, &Env) → layout → paint → DrawList → Renderer`. Обработчики — `Fn(&mut S)`.

## Инварианты (не ломать)

- **Ядро не знает про окно и GPU.** `view/layout/ui/text` собираются с `--no-default-features`.
  Всё платформенное — в `app.rs`, всё wgpu — в `render.rs`.
- **Кадр только по делу.** В простое 0% CPU. Нужен кадр без ввода — выставляй `animating`
  (идёт анимация) или `wake_in` (таймер), а не рисуй непрерывно.
- **id узла = `child_id(parent, index, key)`**, одинаково в layout и paint. На нём держатся пружины,
  скролл, фокус, кэш списка. Меняешь обход дерева в одном месте — меняй в обоих.
- **Один проход layout.** Каждый узел раскладывается один раз; повторный вызов `layout()` для
  поддерева допустим только для строк ленивого `list`: в paint (видимые строки) и в `layout()`
  самого списка, когда сменилась ширина (переизмеряются строки, что были на экране).
- **Пиксельная сетка.** `Ui.scale` (точек → пикселей) ставит раннер каждый кадр. Painter привязывает
  к пикселям края квадов (`Xf::rect_px`, линия не тоньше 1 px), позицию текста и смещение скролла —
  при покраске, не в layout. Что плавно растёт или едет на пружине внутри контрола (ручка тумблера,
  линза `tab_bar`), рисуется с `Xf { px: 0.0, .. }` без привязки, иначе видны ступеньки.
- **Новый виджет** = вариант `Kind` + ветка в `layout()` + ветка в `Painter::paint` + конструктор
  + экспорт в `lib.rs`/`prelude` + тест в `tests/interaction.rs` + строка в README.
  Составной виджет поверх стека (как `split` — `hstack` с `Extras::split`) — ветки в `layout()` и
  paint с guard на `Extras`, обход дерева остаётся стековым (`docs/decisions/007-*`).
- **Новый виджет берёт цвета и размеры из темы** (`Theme`, поле в `Controls`/`Palette`), а не из литералов:
  узловые стили — через `Role` и `theme::apply`, остальное — `lx.look` / `self.look` в layout и Painter.
  Явный модификатор всегда побеждает тему.
- **Ввод** идёт через `Hit`/`Action`, собранные при покраске; порядок в списке = порядок по Z.
- **Полоса прокрутки — свой слой**: копится в `Painter::bars` и рисуется (с hit и zone) в `flush_bars`
  в конце дерева и каждого слоя-поповера и перед скримом модалки. Поверх всего в своём слое, под
  поповерами/меню/модалками. Не рисуй полосу прямо в ветке `Kind::Scroll`.
- **Шейдер должен работать в WebGL2**: без storage-буферов, семплинг в ветвлениях только
  `textureSampleLevel`, производные (`dpdx`) — до любых `if`.
- **Цвет — гамма-пространство**, не-sRGB формат поверхности; в шейдер уходят sRGB-значения как есть.
- **Зависимости**: новая тяжёлая — только optional под фичей и с замером размера wasm.

## Как проверять (обязательно перед «готово»)

1. `cargo test`. Поведение ввода проверяется тестами на `Ui` без окна — добавляй тест на каждый новый жест.
2. Визуальное — кадром через `--screenshot`, и **смотри на картинку**, а не только на код выхода.
3. Меняешь шейдер/рендер/`app.rs` — пересобери web и прогони в браузере
   (Playwright WebKit и Chromium лежат в `~/Library/Caches/ms-playwright`, драйвер `playwright-core@1.64.0`).
4. В отчёте разделяй: проверено тестом / увидено на кадре / не проверено. Живое окно и настоящий
   Safari проверяет человек — говори это прямо.

API `wgpu 30`, `glyphon 0.12`, `cosmic-text 0.19`, `winit 0.30` заметно новее того, что помнит модель.
Перед использованием незнакомого вызова смотри исходник в `~/.cargo/registry/src/*/<crate>-<ver>/`
(`grep -n "pub fn имя"`), а не угадывай.

## Команда агентов

Главная сессия — координатор: держит план, режет задачи, проверяет результат. Код по возможности
пишут агенты из `.claude/agents/`:

| Агент | Модель | Когда |
| --- | --- | --- |
| `coder` | sonnet | Простое и локальное: виджет по образцу, модификатор, тест, правка примера, README, мелкий баг в одном файле |
| `engineer` | opus | Сложное: рендер и шейдеры, физика/жесты, текст, производительность, баг с неясной причиной |
| `architect` | fable | Только проектирование: новый слой, смена модели данных, разбиение на крейты. Возвращает план, код не пишет |

Правила делегирования:
- Одна задача — один агент. В задании: цель, файлы, что уже исключено, критерий готовности, как проверить.
  Не пересказывай код — давай пути и номера строк.
- Независимые задачи запускай параллельно в одном сообщении; задачи, трогающие один файл
  (особенно `ui.rs`), — последовательно или в отдельных worktree.
- Агент возвращает **короткий отчёт** (до 15 строк): что сделал, какие файлы, чем проверил, что не проверено.
  Никаких дампов файлов и логов в ответе.
- Не делегируй то, что решается парой вызовов. Не перепроверяй руками то, что уже отдал агенту, —
  дождись отчёта и проверь итог командами из раздела «Как проверять».
- Архитектурное решение сначала идёт в `docs/` (короткая запись: что решили и почему), потом в код.

## Экономия контекста и токенов

Держи контекст сессии **ниже 600k**. Подходишь к границе — зафиксируй состояние в
`docs/ROADMAP.md` (сделано / в работе / следующее) и продолжай в новой сессии или после `/compact`.

- Ищи `grep -n`, читай диапазон строк; не читай файл целиком, если нужен кусок. `ui.rs` и `render.rs` большие.
- Вывод команд фильтруй (`grep -E "^(warning|error)" -A8 | head`), не лей в контекст полные логи сборки.
- Скриншот смотри один раз и по делу; нужен фрагмент — сначала обрежь. Не открывай картинку, чтобы
  подтвердить то, что уже подтвердил тест.
- Правки делай точечно (`Edit`), а не переписыванием файла. Несколько правок — одним сообщением.
- Не перечитывай файл после правки и не повторяй в ответе код, который только что записал.
- Широкий поиск по чужому коду (реестр cargo, сторонний репозиторий) отдавай агенту `Explore`:
  в основной контекст возвращается вывод, а не файлы.
- Не создавай планов и заметок в файлах, кроме `docs/ROADMAP.md` и записей об архитектурных решениях.

## Стиль

- Комментарий объясняет «почему», а не «что». Публичный API — с doc-комментарием и примером, если неочевидно.
- Без `unsafe` — с одним исключением: `src/macos.rs` (`cfg(target_os = "macos")`, фича `app`), вызовы
  AppKit через `objc2` тех версий, что уже тянет winit. Каждый блок — с `// SAFETY:`. Новый `unsafe`
  в другом файле или другая платформа — только отдельным решением в `docs/decisions/`.
- Без `unwrap()` на пользовательских данных (decode, svg, markdown возвращают `Result` или деградируют).
- Имена виджетов и модификаторов — короткие, как в SwiftUI; новый модификатор не должен дублировать существующий.
- Отвечай пользователю по-русски.
